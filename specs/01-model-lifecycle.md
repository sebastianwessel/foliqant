# Model lifecycle

## Common CLI behavior

Commands: `setup`, `doctor`, `schema`, `fetch`, `prepare`, `quantize`, `train`, `customize`, `evaluate`, `calibrate`, `audit`, `merge`, `export`, `verify`. Use argparse; all file paths are explicit. `--help` never imports MLX or accesses network. Success emits a concise JSON result on stdout; diagnostics go to stderr. Exit codes: 0 success, 2 input/contract failure, 3 dependency/environment unsupported, 4 backend/IO failure, 5 integrity or lineage failure, 130 user interruption. No automatic remote fallback or retry of training.

Configuration is UTF-8 YAML or JSON, maximum 1 MiB. Configuration and JSONL sources must be regular local files; reject symlinks, pipes and devices before reading and verify the opened descriptor to prevent a special-file race. Reject duplicate keys, YAML tags/aliases, nonfinite numbers, unknown fields and unsupported schema versions. Paths in config resolve relative to that config, without environment interpolation. Runtime outputs use explicit paths, never `latest`. YAML uses JSON-style booleans and decimal numbers: true/false are booleans; yes/on, timestamps and leading-zero numbers remain strings and fail numeric/boolean fields. Anchors are rejected as well as aliases and explicit tags. UTF-8 must contain valid Unicode scalar values. Config validation completes before launching a backend. Default timeout is 3600 seconds, configurable from 1 through 604800. Output paths must not already exist; no force/overwrite flag in version one.

## 1. Prepare data

`prepare --config FILE --output DIR` reads local JSONL sources with rights declarations. Each record carries global ID, source ID, language, group keys, messages, and provenance classification. The last message is the sole supervised completion; previous assistant turns remain conversation context. Permit one leading system message and alternating user/assistant turns; final message must be assistant and preceding message user. All content is nonempty text; no tool messages, images, or executable formats in this version.

Use transitive union of shared group keys and exact normalized conversation hashes. Normalize message text with Unicode NFC and LF newlines; preserve case, internal whitespace, roles, and order. Reject duplicate IDs and exact duplicate conversations rather than silently dropping records. If any record in a connected component is private, the component retains that classification. No claim of automatic semantic near-duplicate or PII detection is allowed; users must supply family/customer/thread/translation grouping keys and review data.

Split by connected component, not row. Require at least four components. Sort components by SHA-256 of UTF-8 `seed + NUL + lexicographically-smallest-record-id`. For N components, validation, calibration, and test each receive max(1, floor(N * configured fraction)); train receives the remainder, which must be positive. Fractions default to 0.1 each and their sum must be below 1. Assign sorted components in validation, calibration, test, train order. Preserve records in ID order within each partition. Ratios count components and need not equal row ratios. Emit counts by partition/language/source, exact assignment, source hashes, declarations, and checksummed chat-only JSONL files. Retain full validated records separately for evaluation. Input ordering must not alter assignment or dataset content identity.

Training permission, permission to contribute to shared training, model-redistribution permission, and commercial-use assessment are separate declarations. Private research may use research/non-commercial sources whose terms permit that activity. Preserve commercialUse and restrictions in source rights; commercial clearance is not required for a lawful local research run. `sharedTrainingAllowed` defaults to false; shared training requires explicit true for every new source. `prepare` requires explicit `trainingAllowed: true`; it records but never certifies legal permission. Private sources require an authorization reference. Synthetic or teacher-produced data, and any records not reviewed by a person, are permitted and always make the derived dataset/evaluation diagnostic. No external dataset is silently ingested, and no model self-reported confidence is treated as a training label for correctness.

## 2. Fetch and quantize

`fetch --repo OWNER/NAME --revision SHA --license REF --output DIR` is the explicit general model acquisition command. The pinned setup profile also downloads model assets under the bounded rules in `07-local-setup.md`. Require a 40-character immutable commit revision. Download via huggingface_hub, allowing Safetensors shards/index, tokenizer/config JSON, tokenizer model/vocabulary/merges, README and LICENSE files; never load repository Python, pickle weights, or trust_remote_code. Copy regular file bytes from the HF cache; final artifact contains no symlinks. Record repository, revision, license declaration and full file hashes. Reject missing config, tokenizer, or Safetensors weights. `fetch` accepts a declared license reference; it is not automatic license approval.

`quantize --model DIR --bits 4|8 --group-size 64 --output DIR` verifies a checkpoint or merged artifact, preserves its stage/customer then invokes the actual MLX converter. Record parent hash and precision change. Never call dequantization lossless reconstruction. Architecture support is checked before training; unsupported conversion returns a typed failure, not a different model.

## 3. Shared training and customer customization

`train --config FILE --model DIR --dataset DIR --output DIR` creates a shared LoRA run. `customize` has the same flags plus required `--customer ID` and requires a parent artifact with kind merged and stage shared, or kind quantized with stage shared whose direct parent snapshot has kind merged and stage shared. Reject any customer-stage ancestor. Shared `train` accepts checkpoint/upstream, merged/shared, or their directly derived quantized artifacts; it rejects any customer ancestor and requires `sharedTrainingAllowed: true` for every source in the new dataset. Do not attach a v1 adapter to a v2 parent. Each dataset records SHA-256 hashes of normalized full conversations, prompt-only messages (excluding final reference), and each original group key, together with global record ID and component identity. Each adapter carries the union of entries for every record submitted for train/validation plus all model and warm-start ancestors (a conservative potential-exposure index, not an exact sampled-batch log); merge/quantization/export preserve it as an inventoried `leakage.jsonl` file. Evaluation on calibration/test rejects intersection against all model/adapter training ancestry by record ID, group-key hash, conversation hash or prompt hash. This detects exact declared/content overlap, not semantic similarity or unknown upstream pretraining leakage. Training validates all hashes before loading weights; exact parent identity is part of every adapter manifest.

Run actual MLX LM LoRA/QLoRA. Quantized parents use QLoRA; unquantized parents use LoRA. Only LoRA is in this initial method contract; full-weight training and DoRA are not advertised. Config freezes seed, steps, layer count, learning rate, batch size, accumulation, sequence length, rank, scale, dropout, validation cadence, checkpoint cadence, gradient checkpointing, prompt masking and timeout. Pass all selected values explicitly to the pinned backend. `steps` counts microbatches and must be divisible by `gradientAccumulation`; both train and validation partitions must contain at least `batchSize` records. Actual tokenization must expose at least one supervised token per record, and the prompt token IDs must be a prefix of the complete sequence or preparation for this tokenizer fails explicitly. Mask prompt loss; no implicit data truncation. Preflight tokenization rejects a record longer than configured sequence length; users explicitly curate/chunk before training. Training process receives a private directory containing train and validation only, never calibration/test.

Completed adapter runs must have nonempty valid adapter tensors and adapter configuration, finite observed loss, output hashes, backend versions, parent/dataset identities, resolved config, measured duration and backend-reported peak memory when available. Unavailable metrics are null with a reason, never zero. A subprocess success without verified adapter outputs is failure.

`--warm-start DIR` is optional on train/customize. It requires a completed compatible adapter with the exact same parent hash, stage/customer, rank, scale, dropout, layer count and resolved target keys. Learning rate, seed, dataset and additional step count may differ and are recorded. It creates a new run linked to the prior adapter. Document that this reloads adapter weights; it does not promise restoration of optimizer state or bitwise continuation. No completed run is mutated.

## 4. Evaluation

`evaluate --model DIR [--adapter DIR] --dataset DIR --split validation|calibration|test --config FILE --output DIR` verifies lineage and calls real generation. Strip only the last reference assistant completion; preserve the prompt messages and exact chat template. Use temperature zero, fixed seed, bounded max output tokens, and an explicit maximum example count (omitted means all; otherwise select the first min(maxExamples, available) record IDs in lexical order). Never substitute the reference answer on failure. Model failures produce a failed command rather than a partially successful report.

For every row record ID/language/source/tags, generated text, reference, elapsed time, token count, mean generated-token log probability where the pinned backend exposes it, JSON validity, schema validity when configured, exact correctness, and configured field metrics. String correctness is stripped exact text equality; if both reference and prediction parse as JSON, use canonical JSON structural equality. No LLM-as-judge. Ignore no fields implicitly. Optional output JSON Schema must be a single local Draft 2020-12 document, validated with check_schema before generation; allow only same-document fragment $ref/$dynamicRef and disable all external retrieval. Copy and hash its exact bytes into the evaluation artifact. Format keywords remain annotations, not extra validators. Predicted evidence quotes must occur exactly in the supplied input messages when the configured evidence pointer is present. JSON is required only when outputSchema, evidencePointer or a nonempty fieldPointers list is configured. Otherwise a plain-text prediction may be correct; jsonValid is descriptive. Only applicable validators affect eligibility/correctness. Strict JSON rejects duplicate object keys and NaN/Infinity. Structural equality compares objects by exact keys and values, arrays in order, strings exactly, booleans separately from numbers, null only with null, and finite numbers numerically (1 equals 1.0, true does not equal 1). A configured field missing from either reference or result is false. A configured evidencePointer must resolve to a nonempty string or nonempty list of nonempty strings; each quote must be an exact substring of at least one supplied input message, otherwise evidenceValid is false. Reference output must satisfy configured JSON/schema/evidence requirements before any model generation starts, or the command fails as invalid input. Aggregate counts/rates and source/language slices; zero denominator yields null. Metrics are diagnostic, not automatic legal correctness.

Bind the report to hashes of model/adapter/tokenizer/template/config/parser version/runtime versions and dataset/split/selected IDs. The deployment-profile hash excludes dataset and split so calibration/test results can share the same profile, but includes every generation/scoring choice. Parent+adapter, merged, and quantized variants are distinct profiles. Persist predictions privately; stdout shows only counts and paths, not message text.

## 5. Calibrate and audit an acceptance policy

`calibrate --evaluation DIR --max-error FLOAT --min-accepted INT --output DIR` requires a complete calibration-split evaluation and finite mean-generated-token log probabilities. It never reads test labels. Rank candidate thresholds among observed scores; accept valid results with score >= threshold. Select one predetermined representative per dataset component: the lexicographically smallest record ID, before reading model outputs or labels. Require that every component represented in the evaluation includes that representative (a maxExamples truncation that omits it is ineligible). Apply selection/audit only to those representative rows and identify this unit as `component-representative-v1`; ordinary evaluation metrics still include all evaluated rows. Select the threshold giving maximum accepted count with empirical error <= max-error and count >= min-accepted. Break ties by higher threshold. If none qualifies, emit an abstain-all policy with reason, not a fake successful risk claim. Scores are not probabilities. Version one performs empirical threshold selection, not probability calibration.

`audit --evaluation DIR --policy DIR --output DIR` requires a test-split evaluation, identical deployment profile, same dataset identity as calibration, and disjoint example/group IDs. Fix the policy; do not optimize it on test data. Use the same predetermined representative sampling, then compute accepted count, errors, coverage and a one-sided 95% exact binomial upper error bound using scipy.stats.beta.ppf(0.95, errors+1, accepted-errors), with bound 1 for all errors and null for no accepted cases. Status is `insufficient` below min-accepted, otherwise `meets-bound` if the bound <= max-error, else `fails-bound`. Status applies only to the evaluated sample under the documented independent representative-component/fixed-audit assumptions; synthetic/public diagnostic sets cannot establish production readiness. The error bound describes a fixed policy over representative components, not all messages, customers or future distributions. Relatedness not declared in group keys remains an operator responsibility; no independence guarantee is inferred from splitting alone. Profile changes require new selection/audit. No per-message calibrated probability is exposed.

## 6. Merge, export and verify

`merge --model DIR --adapter DIR --output DIR` verifies the exact parent, runs real fusion, and produces a new merged checkpoint with the adapter's shared/customer stage. Preserve tokenizer/config/template and metadata, retain ancestor identities and rights declarations. Request dequantized fusion for a quantized parent, record precision loss history, and never overwrite inputs.

`export --model DIR --format checkpoint|gguf --output DIR` accepts a verified merged checkpoint. Checkpoint export produces ordinary Safetensors/config/tokenizer artifacts; GGUF conversion runs a pinned supported converter for the actual architecture. Unsupported architectures fail explicitly before expensive work. A filename or successful subprocess alone is not a compatibility check: parse tensor/GGUF metadata and include independent-runtime loading in release evidence. No arbitrary remote converter code or model Python is executed. Immutable export manifests record compatibility as unverified. A recorded real smoke run supplies external release evidence bound to the export artifactId; it does not mutate that manifest or make verify an inference command.

`verify DIR` recalculates inventory hashes/sizes and validates the manifest and safe path boundaries; reject missing, extra unlisted, duplicate, symlink, absolute, or traversal files. Artifact content identity is SHA-256 over canonical manifest JSON excluding the identity field; file hashes are part of that manifest. Completed artifact manifests never refer to mutable aliases. Parent inventories/identities and source rights are included transitively as provenance, without embedding parent weights. Verification proves integrity and recorded lineage, not independent legal clearance or model quality.

## 7. Health, schemas, and packaging

`doctor` reports Python/platform, required backend versions, MLX import/device status and free disk without downloading or executing training. It has no model argument in v1; model compatibility is checked by actual model operations. On unsupported hosts it clearly separates usable offline/data commands from unavailable MLX commands. `schema --output DIR` exports deterministic JSON Schemas from canonical typed contract classes; `schema --check DIR` fails on drift. Installation is `uv sync --extra mlx --group dev` on supported Apple Silicon; offline/data tests install without MLX. Exact pins and lock resolution are recorded in the dependency research before readiness.

## Artifact naming and output locations

Generated artifact names do not act as mutable aliases. Prepare/train/customize use their resolved config name. Other names are: fetch `checkpoint-{revision[:12]}`, quantize `q{bits}-{modelArtifactId[:12]}`, evaluate `evaluation-{modelArtifactId[:12]}`, calibrate `policy-{evaluationArtifactId[:12]}`, audit `audit-{policyArtifactId[:12]}`, merge `merged-{adapterArtifactId[:12]}`, and export `export-{mergedArtifactId[:12]}`. ArtifactId remains the full immutable identity.

All artifact-producing commands require a new explicit output directory. Sibling lock path is `.<output-name>.lock`, private workspace is `.<output-name>.run-<runId>`, and staging is `.<output-name>.staging-<runId>` in the output parent. RunId is 32 lowercase hexadecimal characters from UUID4 without separators. Workspace contains run.json and backend.log; worker request/result files and partial outputs remain inside it. Successful cleanup removes staging and lock but retains the private run workspace as evidence; failure cleanup removes only the owned lock, not partial evidence. A crash may leave a lock requiring manual inspection. Lock contents are exactly runId, pid and workspacePath; pid alone never authorizes removal or killing. Atomic file writes use private sibling temporary files and os.replace; output publication never replaces an existing destination.

Schema generation is a non-artifact operation: --output requires a new/empty directory; --check reads an existing directory and does not change it. Updating committed generated schemas uses a fresh temporary generation directory plus an explicit reviewed copy, never a force option on immutable model artifacts.
